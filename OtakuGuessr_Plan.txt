# OtakuGuessr — Implementation Plan (Version 1 MVP)

> [!IMPORTANT]
> This plan must be approved before any code is written. It covers file structure, database schema, component breakdown, API routes, and build order.

---

## 1. Technology Stack

| Layer | Choice | Rationale |
|---|---|---|
| Framework | **Next.js 14 (App Router)** | SSR, RSC, API routes, Vercel-native |
| Language | **TypeScript** | Type safety, DX |
| Styling | **Tailwind CSS + shadcn/ui** | Fast, modern dark-mode UI |
| Database | **PostgreSQL via Prisma** | Relational, scalable, type-safe ORM |
| Auth | **NextAuth.js v5** | Email/password + OAuth (Google, Discord) |
| Image CDN | **Cloudinary** (abstracted behind a helper) | Easy swap to S3 |
| Audio | **HTML5 `<audio>`** | Zero deps for MVP |
| Caching | **Redis (Upstash)** | Rate limiting, daily challenge caching |
| Deployment | **Vercel + Neon (serverless Postgres)** | Zero-config production |
| Anime Data | **AniList GraphQL API** (seed script) | Rich, free, well-structured |
| Search | **PostgreSQL full-text search + trgm** | Fuzzy autocomplete without extra service |

## 3. Database Schema (Prisma)

```prisma
// Core content models
model Anime {
  id            String   @id @default(cuid())
  anilistId     Int      @unique
  title         String                     // Romaji
  titleEnglish  String?
  titleNative   String?                    // Japanese
  synonyms      String[]
  coverImage    String
  bannerImage   String?
  year          Int?
  season        String?                    // WINTER|SPRING|SUMMER|FALL
  format        String?                    // TV|MOVIE|OVA|ONA|SPECIAL
  status        String?                    // FINISHED|RELEASING|NOT_YET_RELEASED
  episodes      Int?
  studios       String[]
  genres        String[]
  tags          String[]
  source        String?                    // MANGA|ORIGINAL|LIGHT_NOVEL|...
  score         Float?                     // AniList mean score
  popularity    Int?
  description   String?
  contentType   String   @default("ANIME") // Extension point: MANGA|MANHWA
  
  characters    Character[]
  screenshots   Screenshot[]
  openings      Opening[]
  dailyChallenges DailyChallenge[]
  
  createdAt     DateTime @default(now())
  updatedAt     DateTime @updatedAt
  
  @@index([title])
  @@index([contentType])
}

model Character {
  id            String   @id @default(cuid())
  anilistId     Int?     @unique
  name          String
  nameNative    String?
  image         String
  silhouette    String?  // Pre-processed silhouette image URL
  description   String?
  
  animeId       String
  anime         Anime    @relation(fields: [animeId], references: [id])
  
  dailyChallenges DailyChallenge[]
  
  @@index([name])
}

model Screenshot {
  id            String   @id @default(cuid())
  imageUrl      String
  blurredUrl    String?  // Pre-blurred version for hint reveal
  episodeInfo   String?  // Stored but NOT shown to user
  difficulty    Int      @default(3) // 1-5
  
  animeId       String
  anime         Anime    @relation(fields: [animeId], references: [id])
  
  dailyChallenges DailyChallenge[]
}

model Opening {
  id            String   @id @default(cuid())
  audioUrl      String
  title         String?
  clipStart     Int      @default(0)   // seconds
  clipDuration  Int      @default(30)  // seconds
  
  animeId       String
  anime         Anime    @relation(fields: [animeId], references: [id])
  
  dailyChallenges DailyChallenge[]
}

// Daily challenge system
model DailyChallenge {
  id            String   @id @default(cuid())
  date          DateTime @db.Date         // UTC date
  mode          GameMode
  
  animeId       String?
  anime         Anime?   @relation(fields: [animeId], references: [id])
  characterId   String?
  character     Character? @relation(fields: [characterId], references: [id])
  screenshotId  String?
  screenshot    Screenshot? @relation(fields: [screenshotId], references: [id])
  openingId     String?
  opening       Opening? @relation(fields: [openingId], references: [id])
  
  scores        Score[]
  
  @@unique([date, mode])
  @@index([date])
}

enum GameMode {
  SCREENSHOT
  CHARACTER
  OPENING
  ANIDLE
}

// User system
model User {
  id            String   @id @default(cuid())
  email         String   @unique
  emailVerified DateTime?
  name          String?
  image         String?
  password      String?  // hashed, null for OAuth users
  
  role          Role     @default(USER)
  
  accounts      Account[]
  sessions      Session[]
  scores        Score[]
  streak        Streak?
  
  createdAt     DateTime @default(now())
  updatedAt     DateTime @updatedAt
}

enum Role {
  USER
  ADMIN
}

model Account {
  // NextAuth.js standard Account model
  id                String  @id @default(cuid())
  userId            String
  type              String
  provider          String
  providerAccountId String
  refresh_token     String?
  access_token      String?
  expires_at        Int?
  token_type        String?
  scope             String?
  id_token          String?
  session_state     String?
  
  user              User    @relation(fields: [userId], references: [id], onDelete: Cascade)
  @@unique([provider, providerAccountId])
}

model Session {
  id           String   @id @default(cuid())
  sessionToken String   @unique
  userId       String
  expires      DateTime
  user         User     @relation(fields: [userId], references: [id], onDelete: Cascade)
}

// Score & Leaderboard
model Score {
  id              String   @id @default(cuid())
  userId          String?  // null = anonymous (local storage only)
  user            User?    @relation(fields: [userId], references: [id])
  
  challengeId     String
  challenge       DailyChallenge @relation(fields: [challengeId], references: [id])
  
  mode            GameMode
  won             Boolean
  attempts        Int
  points          Int
  timeTaken       Int?     // seconds
  shareText       String?  // Cached share card text
  
  createdAt       DateTime @default(now())
  
  @@unique([userId, challengeId])
  @@index([mode, createdAt])
  @@index([points])
}

// Streak system
model Streak {
  id            String   @id @default(cuid())
  userId        String   @unique
  user          User     @relation(fields: [userId], references: [id])
  
  currentStreak Int      @default(0)
  longestStreak Int      @default(0)
  lastPlayedAt  DateTime?
  freezesAvailable Int   @default(1)
  
  updatedAt     DateTime @updatedAt
}
```

## 4. Game Logic Design

### 4.1 Scoring Algorithm

| Mode | Max Points | Deduction per wrong guess |
|---|---|---|
| Screenshot | 1000 | –150 (each blur reveal) |
| Character | 1000 | –150 (silhouette reveal) |
| Opening | 1000 | –100 (more audio revealed) |
| Anidle | 1000 | –100 per guess (max 6) |

Speed bonus: `+100` if solved in under 30s, `+50` if under 60s.

### 4.2 Anidle Attribute Comparison

| Attribute | Type | Feedback |
|---|---|---|
| Year | Numeric | 🟢 exact / 🟡 ±3 years / 🔴 wrong + ↑↓ arrow |
| Season | Categorical | 🟢 / 🔴 |
| Format | Categorical | 🟢 / 🔴 |
| Episodes | Numeric | 🟢 / 🟡 ±10 / 🔴 + ↑↓ |
| Genres (top 3) | Set | 🟢 all match / 🟡 partial / 🔴 none |
| Studio | Categorical | 🟢 / 🔴 |
| Source | Categorical | 🟢 / 🔴 |
| Score | Numeric | 🟢 ±0.5 / 🟡 ±1.5 / 🔴 + ↑↓ |

Max 6 guesses for Anidle.

### 4.3 Screenshot / Character Progressive Reveal

- **Screenshot**: starts maximally blurred (blur-3xl), each wrong guess reduces blur (6 hint levels)
- **Character**: starts as silhouette, each wrong guess adds color/detail

### 4.4 Opening Progressive Reveal

- Starts with 5s clip
- Each wrong guess: +5s more audio revealed (up to 30s)
- Waveform visualizer (CSS-only for MVP)

### 4.5 Daily Reset Logic

- Challenges generated **at 23:00 UTC the previous day** via Vercel cron job
- Redis cache stores the day's challenges with TTL until end of day
- Selection algorithm: weighted random, avoiding recent repeats (last 30 days), prefer popular anime for first 100 days
- Date key format: `YYYY-MM-DD` UTC

## 5. API Routes

### Daily Challenge APIs
```
GET  /api/daily/screenshot     → { challenge, expiresAt }  (no answer)
GET  /api/daily/character      → { challenge, expiresAt }
GET  /api/daily/opening        → { challenge, expiresAt }
GET  /api/daily/anidle         → { challenge, expiresAt }
```

### Submission APIs
```
POST /api/game/screenshot/submit  { guess: string }  → { correct, answer?, points? }
POST /api/game/character/submit   { guess: string }  → { correct, answer?, points? }
POST /api/game/opening/submit     { guess: string }  → { correct, answer?, points? }
POST /api/game/anidle/guess       { animeId: string } → { attributes[], won, guessesLeft }
```

### Search APIs
```
GET  /api/search/anime?q=&limit=10  → Anime[]  (fuzzy, sorted by popularity)
GET  /api/search/character?q=&limit=10 → Character[]
```

### User/Social APIs
```
GET  /api/leaderboard?mode=&period=daily|weekly  → LeaderboardEntry[]
GET  /api/streak                                 → StreakData
POST /api/streak/freeze                          → StreakData
GET  /api/share/generate?scoreId=               → { text, imageUrl }
```

### Admin APIs (protected)
```
POST /api/admin/daily/generate    Trigger manual challenge generation
POST /api/admin/anime/import      Import from AniList
```

## 7. Caching & Performance Strategy

| Data | Cache | TTL |
|---|---|---|
| Daily challenge (non-answer) | Redis | Until midnight UTC |
| Anime search results | Redis | 1 hour |
| Leaderboard | Redis | 5 minutes |
| User streak | Redis | 15 minutes |
| OG share images | Cloudinary | Permanent |

- Next.js **Route Segment Config** for per-route revalidation
- **`unstable_cache`** for DB queries in RSCs
- Connection pooling via **PgBouncer** (Neon includes this)
- Vercel **Edge Middleware** for rate limiting on submission routes

## 9. Streak Logic

```
On daily completion:
  lastPlayed = today (UTC date)?
    → already played, skip
  lastPlayed = yesterday?
    → streak++
  lastPlayed = 2 days ago AND freezesAvailable > 0?
    → streak preserved, freezesAvailable--
  else?
    → streak reset to 1

longestStreak = max(longestStreak, currentStreak)
```

Streak freeze earned every 7-day streak milestone.

## 13. Production Readiness (30k+ Users)

- **Horizontal scaling**: Vercel serverless functions auto-scale
- **DB connection pooling**: Neon with PgBouncer (max_connections managed)
- **Redis**: All hot-path reads (daily challenge, leaderboard) served from cache
- **Rate limiting**: Upstash rate limit on all submission routes (5 req/min per IP)
- **CDN**: All images via Cloudinary CDN, audio via CDN-backed storage
- **Error monitoring**: Ready for Sentry integration (placeholder)
- **Analytics**: Ready for Vercel Analytics
- **Database indexes**: On all foreign keys, search fields, leaderboard sort columns
